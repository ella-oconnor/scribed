Tech CV

The clean, single-column format used by candidates who land offers at Stripe, Google, and every startup in between. Evidence over aesthetics.

Why this format works

The "Jake's Resume" layout is the industry standard for software engineering roles.

Hiring managers at tech companies spend an average of 7.4 seconds scanning a CV. This format is optimised for both humans and applicant tracking systems (ATS):

  • Single column — ATS parsers can't reliably read two-column or sidebar layouts
  • Standard section headings — Education, Experience, Projects, Technical Skills — in exactly the order recruiters expect
  • No graphics, no skill bars, no icons — anything an ATS can't parse is a liability
  • Dense but readable — you fit maximum evidence into one page without sacrificing scanability
This template is designed for software engineering, data science, product, and technical PM roles. For finance or consulting, use a different format.

Projects matter more than your GPA

In tech, demonstrable projects carry more weight than grades alone.

Unlike finance CVs where university name and grades dominate, tech CVs are judged on what you've shipped. A side project with 200 GitHub stars tells a recruiter more than a first-class degree alone.

The Projects section is where you prove you can build things that work. Every project should answer three questions:

  1. What did you build? — one sentence, plain English
  2. What technology did you use? — the stack, in parentheses
  3. What was the result? — users, stars, performance improvement, award
[Built X] using [Y technology] that [Z result / metric]
✓ Good example Built a CLI tool for automated database migrations using Go and PostgreSQL; adopted by 3 teams internally, 200+ GitHub stars
✗ Weak example Created a project using various technologies for my module coursework

How to write experience bullets

Every line should prove impact, not just describe responsibilities.

Tech recruiters are trained to skip bullets that start with "Responsible for" or "Helped with." Use this formula instead:

[Action verb] + [Technical detail] + [Impact with numbers]

Strong action verbs for tech CVs

Building: Engineered, Architected, Developed, Implemented, Shipped, Deployed

Improving: Optimised, Refactored, Reduced, Automated, Migrated, Scaled

Leading: Led, Designed, Spearheaded, Mentored, Reviewed, Owned

✓ Good bullet Reduced API response latency by 40% by implementing Redis caching layer across 12 microservices
✗ Weak bullet Worked on backend improvements and helped the team with various tasks

The GitHub rule

If you mention a project, link to the code.

Include your GitHub profile URL in the header. For significant projects, add a direct repo link next to the project name. This signals confidence and invites scrutiny — both of which work in your favour if the code is strong.

Before applying, make sure your pinned repos have:

  • A clear README with setup instructions
  • Consistent commit history (not one massive commit)
  • No secrets, API keys, or .env files committed
  • A live demo link if it's a web project
Recruiters will click your GitHub link. Treat your profile as a portfolio — pin your best 4-6 repos and write proper READMEs.

ATS-proof your CV

Most large tech companies use automated screening before a human ever sees your CV.

  • Single column only — multi-column layouts break ATS parsing
  • Standard section headings — "Experience" not "Where I've Worked"
  • No tables, text boxes, or graphics — they're invisible to parsers
  • Mirror keywords from the job posting — if they say "React" and "TypeScript," use those exact words
  • Save as PDF — preserves formatting across systems
  • File name matters — use FirstnameLastname-CV.pdf

What to leave off

Every line on a one-page CV has to earn its place.

✗ Remove these
  • Skill bars or percentage ratings (they're meaningless and ATS-invisible)
  • Photos or headshots (standard in tech to omit)
  • "Proficient in Microsoft Word / Excel" (assumed for any graduate)
  • Full home address (city is enough)
  • References available on request (assumed, wastes a line)
  • Personal statement / objective (your projects speak louder)
  • Graphics, icons, or colour-coded sections
  • Two-column or sidebar layouts
